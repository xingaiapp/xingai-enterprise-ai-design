# Contributing Guidelines

感谢您对 XingAI Enterprise AI Design 的兴趣！

## 我们接受什么内容？

### ✅ 接受

- **架构设计模式** — 企业级 AI 系统的架构决策
- **最佳实践** — 生产环境中验证过的做法
- **案例研究** — 真实项目的架构分析
- **框架和工具** — AI 系统设计框架
- **经验教训** — 失败的案例和学到的东西

### ❌ 不接受

- 营销内容
- 学术论文
- 未经验证的理论
- 特定产品的广告
- 低质量或草草的内容

## 如何贡献

### 1. 创建问题 (Issue)

首先创建一个 Issue，描述您想写的文章：

```markdown
**标题:** [Article] Your Article Title

**受众:** Enterprise Architects / AI Architects / CTOs

**主题:** Brief description

**为什么有价值:** Why should people read this?
```

### 2. 编写文章

查看 [BILINGUAL-POSTS.md](BILINGUAL-POSTS.md) 了解双语要求。

结构：

```
articles/
├── YYYY-MM-DD-slug.md       # 英文版本
└── YYYY-MM-DD-slug.zh.md    # 中文版本
```

### 3. 提交 Pull Request

- 在 PR 中引用相关的 Issue
- 遵循 [BILINGUAL-POSTS.md](BILINGUAL-POSTS.md) 中的检查清单
- 提供 2-3 句的总结

## 写作标准

### 质量要求

- **深度** — 不是表面的解释，要有实际的架构洞察
- **实践** — 基于真实的项目经验
- **清晰** — 专业但易理解
- **原创** — 不复制他人工作

### 长度

- 最少 1500 字
- 通常 2500-3500 字
- 某些情况下可以更长

### 图表和可视化

- 使用 Mermaid 绘制架构图
- 在 `assets/` 中存储其他图片
- 提供清晰的 alt 文本

## 术语和风格

- 参考 [BILINGUAL-POSTS.md](BILINGUAL-POSTS.md) 中的术语对照表
- 保持与其他文章的一致性
- 链接到相关的现有文章

## 审查流程

1. 自动检查（拼写、链接）
2. 内容审查（准确性、深度）
3. 编辑审查（清晰度、一致性）
4. 最终批准

## 问题？

创建一个 Discussion 或发送邮件至 contact@xingai.app
